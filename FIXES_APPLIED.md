# Fixes Applied to CorvinLogs (2026-08-07)

## Issue 1: Systematic Date Divergence (100% of files)

**Problem:**
All 40 trace files were stored in directories named after upload timestamp, but contained
events dated ONE DAY EARLIER. Example:
- Filename: `a5e1103f74f3_20260801T000407Z.jsonl.gz` (directory: `2026-08-01/`)
- Content: `"ts_day": "2026-07-31"` (last line of trace file)

This made date-based queries incorrect and archive organization confusing.

**Root Cause:**
Correct behavior: traces are timestamped when errors occur (ts_day = error date), 
then uploaded the next day. The archive should be organized by ERROR DATE (ts_day), 
not by UPLOAD DATE (file timestamp).

**Fix Applied:**
✓ Reorganized 40 files into directories matching their content's `ts_day` field:
- Moved traces from `2026-07-06/` → `2026-07-05/`
- Moved traces from `2026-08-07/` → `2026-08-06/`
- (And 38 others in the same pattern)

**Verification:**
Directory structure now matches schema intent:
```
traces/htrace-v1/
  2026-07-04/  ← events from July 4
  2026-07-05/  ← events from July 5
  ...
  2026-08-06/  ← events from August 6 (latest)
```
